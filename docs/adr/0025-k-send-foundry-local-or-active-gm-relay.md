# `k.send` on Foundry runs locally when the caller owns the target, otherwise relays to the active GM over the system socket

`k.send(target, funcName, ...args)` keeps its Roll20 signature on Foundry (#159). `target` is a plain runtime string — the scaffold declares no link field; authors keep a partner reference in an ordinary attribute as today. On Foundry it resolves as full UUID, then bare document id, then actor name (first match on duplicates, with a `k.debug` line), Actors only; Roll20 already accepts a character id or name in `@{<target>|character_name}`, so both targets address the same way. Arguments cross by value on both targets (Foundry JSON round-trips them so authored code can't lean on live references), the call is fire-and-forget (`Promise<void>`) on both, and the receiving function gets the same minimal `trigger` Roll20 supplies — `{name:'k-network-call', rollData:{funcName, args}}` — with no Foundry-only sender info. The registered-function registry stays system-wide; the executing client builds a fresh alias-layer context bound to the target actor, calls the function, and flushes its batched writes to that actor.

Delivery is the trade-off. Roll20's chat round trip lets any player trigger a function on a character they don't control; a purely local Foundry call would reject the target write for a non-owner, and an always-relay design would make every send — including to your own character — depend on a GM being online. We chose the middle: if the calling client has OWNER on the target, run locally; otherwise emit `{type:'k-send', target:<UUID>, funcName, args}` on `system.<systemId>` (listener registered by the generated entry file at `init`), resolving the target to a UUID *before* emitting so a bad name fails on the caller with a debug line and every client agrees on the target. Every client receives the message; only the one whose `game.user` is `game.users.activeGM` executes, which is Foundry's built-in single-elector and avoids double writes. With no GM connected the call is logged and dropped, mirroring Roll20's `&{noerror}` swallow. The Roll20 path is untouched.
