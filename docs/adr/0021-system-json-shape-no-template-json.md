# system.json shape; template.json is not generated

k-scaffold generates a single `system.json` per Foundry build and does not generate `template.json` at all. Foundry's legacy `template.json` entered its deprecation period in v14.352 ([foundryvtt/foundryvtt#13429](https://github.com/foundryvtt/foundryvtt/issues/13429), building on [#10444](https://github.com/foundryvtt/foundryvtt/issues/10444)): systems may declare Actor/Item sub-types entirely via `documentTypes` in `system.json`, paired with `TypeDataModel`/`defineSchema()` classes (ADR 0011). Since this project targets Foundry v14+ only (`compatibility.minimum: 14` per ADR 0018), there is no legacy client to support and no reason to maintain a second, redundant type-declaration file.

`system.json`'s `documentTypes.Actor.<modeName>` and `documentTypes.Item.<itemTypeName>` entries are generated as empty stubs (`{}`) directly from `+mode` (ADR 0005) and `fieldset(foundryItemType=...)` (ADR 0008) declarations in the cascade schema — they exist only to register the sub-type name with Foundry. The actual field schema lives entirely in the generated DataModel classes (ADR 0011), registered via `CONFIG.Actor.dataModels`/`CONFIG.Item.dataModels` in generated JS, not in `system.json` itself.

`system.json`'s remaining fields split three ways:

- **Explicit in the consuming project's `k.config.mjs` `foundry: {}` block** (ADR 0018): `id`, `title` (both required, never derived), `compatibility.minimum` (defaults to 14). `compatibility.verified` defaults to mirror `minimum` unless explicitly overridden; no `compatibility.maximum` is set.
- **Reused from the consuming project's own `package.json`**, matching how Roll20 output already reads project metadata rather than duplicating it in k.config.mjs: `version` ← `version`, `description` ← `description`, `authors` ← `author`/`contributors`, `url` ← `homepage`, `bugs` ← `bugs.url`, `license` ← `license`. `manifest`/`download` are constructed from `package.json`'s `repository` field plus the resolved version, using the standard GitHub Releases convention: `manifest: https://github.com/<owner>/<repo>/releases/latest/download/system.json`, `download: https://github.com/<owner>/<repo>/releases/download/v<version>/<repo>.zip`.
- **Hardcoded by the generator**: `esmodules`/`styles` point at k-scaffold's own fixed Foundry build-output paths — the generator already knows where it wrote the compiled JS/CSS, so these are never a config surface.

`packs` (compendiums, deferred per [ADR 0017](0017-compendiums-and-active-effects-deferred.md)), `socket`, `grid`, `initiative`, `primaryTokenAttribute`/`secondaryTokenAttribute`, `background`/`media`, `readme`, `changelog`, `flags`, and `relationships` are all omitted from v1's generated `system.json` — none are needed for a working Actor/Item system, and each can be added later without disturbing this shape.
