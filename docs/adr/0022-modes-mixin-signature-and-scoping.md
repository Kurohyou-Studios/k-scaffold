# `+modes`/`+mode` signature, required-ness, and scoping

`+modes` takes `{name, defaultActiveTab}` — the same shape as `+tabs` minus `persistent`, which is dropped as an author-facing argument and hardcoded to always-persistent: unlike a tab, a mode isn't a transient UI state worth ever resetting on reload. `+mode` takes `{name, foundryActorType, button, container}` — the same shape as `+tab` plus `foundryActorType`, which is **required** and never derived from `name`: a tab's display name is freely renameable, but `foundryActorType` becomes a permanent `system.json documentTypes.Actor.<key>` embedded in every world's save data, so silently deriving it from a cosmetic display name is a foot-gun. Duplicate `foundryActorType` values across a sheet throw at compile time, mirroring `+tab`'s existing duplicate-name guard.

`+modes`/`+mode` is required authoring for any project targeting `foundry` (ADR 0018) — there is no implicit default mode synthesized for sheets that skip it, since a mode is a real document boundary (a Foundry Actor type) that can't be guessed. Roll20-only projects have no need for it and can ignore it entirely (ADR 0015's "purely additive" still holds: nothing about `+modes` existing changes Roll20-only output). If `targets` includes `'foundry'` and no `+mode` was declared, the build throws once the cascade schema is fully built, before the Foundry emitter runs — never a partial or broken `system.json`.

A mode is a document boundary, so `+mode` cannot nest inside another `+mode` (compile-time throw, mirroring the existing `+tabs`-inside-`+tabs` guard). `+tabs`/`+tab` nesting inside a `+mode`'s block is unaffected: `+mode` decomposes to `+tab` on Roll20 (ADR 0005), pushing onto the same `__kscaffold_section_stack` a `+tab` call would, so existing tab-nesting support applies for free. Because modes can't nest, mode-ownership tracking needs no stack — a single mutable value (mirroring `k.repeatingPrefix`'s pattern for repeating sections) is set for the duration of a `+mode`'s block and cleared after, tagging every attribute/button/fieldset declared inside with its owning `foundryActorType` for per-Actor-type `DataModel` codegen (ADR 0011). Content inside `+modes` but outside any `+mode` remains legal for Roll20-only builds (mirroring `+tabs`' "content before the tabs"), but is a compile-time error for Foundry builds, since no Actor type would own it.
