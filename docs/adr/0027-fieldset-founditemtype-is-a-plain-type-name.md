# `foundryItemType` is a plain type-name string; schema and row defaults come from elsewhere

`fieldset`'s `foundryItemType` argument (ADR 0008) carries nothing but the Foundry Item sub-type name — e.g. `fieldset({name:'inventory', foundryItemType:'weapon'})`. It does not declare `defineSchema()` inline, and it does not carry per-field default values for newly created rows.

The Item's `defineSchema()` is generated by the compiler walking the fieldset's own row/column mixin declarations, exactly like an Actor mode's DataModel (ADR 0011, ADR 0021) — `foundryItemType` only supplies the type name that ties those generated fields to a registered `Item` sub-type in `system.json`'s `documentTypes` (ADR 0021). Per-field defaults for newly created rows come from each column's own attribute-mixin `value` argument (ADR 0019); `fieldset` doesn't duplicate that.

Foundry Items require a `name` field outside `system` data. A row added to an Item-backed fieldset gets a placeholder name — `"New <ItemType>"`, title-cased from `foundryItemType` — editable immediately via Foundry's native Item name field on the sheet. This avoids inventing a new required "label column" convention; it matches how Foundry's own "Create Item" UI behaves, and stays independent of the informal `label` attribute convention `+dynamicOptions` (#168) uses loosely for its own display purposes.
